1. Project Overview

InstalliQ.ai (formerly Field Proof) is a full-stack, mobile-responsive web application designed exclusively for FASTSIGNS of Waltham. It serves as a comprehensive signage installation project management platform that enables field installers and administrators to:

  • Upload and manage installation photos with AI-powered auto-tagging
  • Schedule and track installation jobs via an interactive calendar
  • Process work order PDFs using AI (GPT-4o Vision) for automated data extraction
  • Send customer email notifications for booking confirmations and updates
  • Generate PDF reports and export project data
  • Manage users with a three-tier role hierarchy and complete data isolation
  • Track job timers and installation progress in real time

The platform streamlines operations, improves project tracking, and enhances communication within the FASTSIGNS organization.

2. Project Scope

2.1 Business Problem

FASTSIGNS of Waltham needed a centralized system to manage signage installation projects, track field operations, schedule installations, and communicate with customers — replacing fragmented manual processes with an intelligent, AI-assisted platform.

2.2 Scope of Work

User Management

  • Three-tier role hierarchy: Super Admin, Admin (franchise locations), and User (field installers)
  • Admins isolated to see only users they created; Super Admin has global oversight
  • Soft-delete with archive/restore functionality
  • Password management: temporary passwords, reset flows, and enforced complexity rules

Authentication & Security

  • Email/phone-based login with bcrypt password hashing
  • Optional Face Recognition login via face-api.js (TensorFlow.js)
  • Two-Factor Authentication (2FA) via Google Authenticator (TOTP)
  • Session-based auth with secure cookies

Project Management

  • Photo upload, viewing, and inline editing from the project detail page
  • AI-powered image analysis for automatic signage tagging
  • Issue reporting and tracking per project
  • PDF report generation and email sharing
  • Bulk export of project images as ZIP files

Installation Calendar

  • Day, week, and month views with drag-based navigation
  • AI-powered auto-fill from uploaded work order PDFs/images
  • Multi-user assignment per event
  • Status workflow: Scheduled, Confirmed, Reschedule, Issue, Completed
  • Customer email notifications with confirmation/reschedule links
  • Weather forecasting integration per job location
  • Export bookings as CSV filtered by status categories

AI Integration

  • Per-admin personalized OpenAI Assistants with customizable instructions
  • Knowledge file uploads (pricing sheets, catalogs) via vector stores
  • AI-driven install time estimation and scheduling suggestions
  • Work order PDF data extraction using GPT-4o Vision

Onboarding

  • Multi-step onboarding form (5 sections) required before app access
  • Captures business info, team details, capabilities, product lists, and install standards
  • Auto-creates personalized AI Assistant on completion

4. System Architecture

Architecture Pattern

The application follows a monorepo full-stack architecture with shared types between frontend and backend:

project-root/ ├── client/ # Frontend (React + Vite) │ ├── src/ │ │ ├── pages/ # Route-level page components │ │ ├── components/ # Reusable UI components │ │ │ └── ui/ # Shadcn/ui primitives │ │ ├── hooks/ # Custom React hooks │ │ └── lib/ # Utilities (auth, query client) │ └── public/ # Static assets, face models ├── server/ # Backend (Express) │ ├── index.ts # Server entry point │ ├── routes.ts # All API route handlers │ ├── storage.ts # Database access layer (IStorage) │ ├── vite.ts # Vite dev/prod server integration │ └── replit_integrations/ # Object storage service ├── shared/ # Shared code │ └── schema.ts # Drizzle ORM schema + Zod types └── package.json

Request Flow

1. Client sends HTTP request to Express server
2. Express middleware checks authentication (session cookie) and authorization (role check)
3. Route handler validates input using Zod schemas from shared/schema.ts
4. Storage layer executes Drizzle ORM queries against PostgreSQL
5. Response returned as JSON (or file stream for exports/downloads)
6. React Query caches response and updates the UI

Timezone Handling

All booking times are stored as UTC in PostgreSQL and converted to US Eastern Time (America/New_York) for display. Frontend uses toEST(), formatEST(), and fromEST() helper functions. Backend uses formatInTimeZone() from date-fns-tz.

6. Authentication & Security

Primary Login

Users authenticate with email or phone number plus password. Passwords are hashed with bcrypt (cost factor 10). Sessions are managed via express-session stored in PostgreSQL using connect-pg-simple.

Face Recognition Login

Optional standalone login using face-api.js (TensorFlow.js). Users register their face via webcam in Account Settings. On login, the browser captures a face, extracts a 128-dimensional embedding, and sends it to the backend. The server compares against all face-enabled users using euclidean distance (threshold: 0.6). Face model files are served from client/public/models/.

Two-Factor Authentication (2FA)

Optional TOTP-based 2FA using Google Authenticator. Implementation:

  • Setup: POST /api/auth/2fa/setup — generates TOTP secret, returns QR code + manual key
  • Verify: POST /api/auth/2fa/verify — validates code and enables 2FA
  • Login Flow: After password check, if 2FA is enabled, returns requires2FA: true. Client shows code input, validates via POST /api/auth/2fa/validate-login
  • Disable: POST /api/auth/2fa/disable — requires password confirmation
  • Libraries: otpauth for TOTP generation/validation, qrcode for QR code generation

Password Security

  • Enforced minimum length, uppercase, number, and special character
  • Password reset via email with time-limited tokens
  • Admin can reset user passwords (generates temp password)

7. Role-Based Access Control

RoleCan CreateVisibilityCapabilities
Super Admin Admin accounts (with location) All admins + all users globally Global oversight, manage AI assistant settings for any admin, configure calendar filter colors, view-only on bookings, cannot create/delete bookings
Admin User accounts only Only users they created (isolated by createdBy) Full calendar management, create/edit/delete bookings, send customer notifications, export data, manage own AI assistant
User (Installer) None Assigned events only View calendar, view project details, upload completion photos, report issues, start/stop job timers

Data Isolation

Achieved through the createdBy field on users and calendar events. Each admin only sees and manages resources they created. The Super Admin bypasses this isolation for oversight. Middleware functions requireAuth and requireAdmin enforce access at the API level.

8. Core Features & Solutions

8.1 Dashboard & Project Management

Problem: Field installers need a quick way to document completed installations with photos and track issues.

Solution:

  • Photo Upload: Multi-image upload via Multer, stored in Replit Object Storage. Images accessible via /objects/* route with fallback to legacy local paths.
  • AI Auto-Tagging: Uploaded images are analyzed by GPT-4o to suggest signage type tags (Channel Letters, Vehicle Graphics, etc.) from a predefined list of 16 categories.
  • Grid/List Views: Toggle between card grid and compact list view for project browsing.
  • Issue Reporting: Users can flag projects with issues and provide descriptions. Filtered via status buttons (All, Issues, No Issues).
  • Inline Editing: Project details (description, job label, tags, customer info) editable directly from the detail page without navigating away.
  • Image Management: Add/delete images from existing projects. Reorder not required.
  • PDF Reports: Generate detailed PDF reports via PDFKit with project images, tags, and metadata. Can be emailed to recipients.
  • Bulk Export: Select individual projects or export all. Images downloaded as a ZIP file organized by job label using the Archiver library.

Key Functions:

  • POST /api/projects — Create project with images
  • POST /api/analyze-image — AI tag suggestion
  • POST /api/projects/export — Bulk ZIP export
  • GET /api/projects/:id/pdf — PDF report generation
  • POST /api/projects/:id/email — Email report

8.2 Installation Calendar

Problem: Scheduling installations across multiple installers with varying job complexity needed intelligent automation.

Solution:

  • Calendar Views: Day, Week, and Month views with color-coded status indicators. Calendar renders events with inline time blocks for scheduled events and all-day markers for unscheduled ones.
  • Status Workflow: Events progress through Scheduled → Confirmed → Completed, with Reschedule and Issue states. Each status has a customizable color (Super Admin configurable).
  • Multi-User Assignment: Events can be assigned to multiple installers via the event_assignments table. User filter dropdown in toolbar.
  • AI Auto-Fill: Upload a work order PDF or image, GPT-4o Vision extracts title, customer name, address, sign types, and dimensions to pre-populate the event creation form.
  • Weather Integration: Calendar header shows current weather + multi-day forecast for Waltham, MA. Individual bookings auto-fetch weather snapshots when an address is provided. Powered by OpenWeather API with caching in weather_cache table.
  • Customer Notifications: Admin manually triggers email notifications via POST /api/notifications/send-schedule-confirmation. Emails include confirmation links with unique tokens. Customers can confirm or request reschedule via public-facing pages.
  • Reschedule Requests: Customers submit reschedule reasons via a public form. Admins review pending requests on the Reschedule Requests page.
  • Job Timers: Installers can start/stop timers on assigned jobs to track actual installation duration.
  • CSV Export: Export bookings filtered by status categories (Scheduled, Confirmed, Reschedule, Issues, Completed) or export all. Downloaded as CSV with columns for title, status, dates, address, assigned users, and more.

Key Functions:

  • POST /api/calendar-events/with-attachments — Create event with file attachments
  • POST /api/calendar-events/extract-file-data — AI work order extraction
  • POST /api/calendar-events/:id/assignments — Assign users to event
  • POST /api/calendar-events/:id/send-assignment-emails — Send notification emails
  • POST /api/calendar-events/export — CSV export by status
  • POST /api/job-timers/:calendarEventId/start — Start job timer
  • POST /api/job-timers/:calendarEventId/stop — Stop job timer

8.3 User Management

Problem: Multi-location franchise operations need isolated user management per admin with centralized oversight.

Solution:

  • Admin Isolation: Each Admin sees only users they created. The createdBy field enforces this at query level.
  • Soft Delete: Users are never hard-deleted. A deletedAt timestamp marks them as archived. Archived users viewable on a separate page and restorable.
  • CSV User Export: GET /api/admin/users/export-csv downloads user list as CSV.
  • Password Reset: Admin can generate temporary passwords for users.
  • Super Admin AI Management: Super Admin can access and manage any admin's AI Assistant settings through the user management interface.

Key Functions:

  • POST /api/admin/users — Create new user/admin
  • PATCH /api/admin/users/:id — Update user
  • DELETE /api/admin/users/:id — Soft-delete user
  • POST /api/admin/users/:id/restore — Restore archived user
  • GET /api/admin/users/deleted — List archived users

8.4 Onboarding

Problem: New admin accounts need to provide business details to personalize their AI assistant before using the app.

Solution: A mandatory 5-section multi-step form that collects:

  1. Business Info: Address, installation range, travel time billing
  2. Team & Scheduling: Team size, scheduling point-of-contact, sub-installer coordination
  3. Capabilities & Equipment: Bucket truck, ladder specs, vehicle graphics, wraps capability
  4. Product Lists & Pricing: Sign types offered, pricing info
  5. Install Time Standards: Standard installation durations for different sign types

On completion, the system auto-creates a personalized OpenAI Assistant by merging the base system prompt with the admin's business details. Users are redirected to /onboarding until completed.

9. AI Integration

OpenAI GPT-4o

The platform integrates OpenAI's GPT-4o model through multiple channels:

Image Analysis & Auto-Tagging

POST /api/analyze-image — Uploads an image to GPT-4o Vision. The AI analyzes the signage photo and returns suggested tags from the predefined 16-category list. Tags are stored as aiSuggestedTags on the project.

Work Order PDF Extraction

POST /api/calendar-events/extract-file-data — Converts PDF pages to images using pdftoppm, sends to GPT-4o Vision, extracts structured data (invoice#, customer name, address, sign types, dimensions). Auto-fills the calendar event creation form.

Install Time Estimation

Uses the OpenAI Assistants API with admin-specific assistants to estimate installation duration, complexity, and recommended crew size. Falls back to direct completions if the assistant call fails.

Per-Admin Personalized Assistants

Each admin gets their own OpenAI Assistant (stored as openaiAssistantId). Created automatically on onboarding completion by merging the global base prompt (OPENAI_ASSISTANT_ID) with the admin's business details. Admins can customize their assistant's instructions and upload knowledge files (pricing sheets, catalogs) via vector stores on the Assistant Settings page.

Intake Dialog

POST /api/intake/create-from-prompt — Natural language scheduling requests (e.g., "next Tuesday morning at 10am for Jones Lang") processed by the AI to extract event details and create bookings.

Key API Endpoints:

  • GET /api/assistant/admin/:adminId/settings — Get assistant config
  • PUT /api/assistant/admin/:adminId/instructions — Update assistant instructions
  • POST /api/assistant/admin/:adminId/files — Upload knowledge file
  • DELETE /api/assistant/admin/:adminId/files/:fileId — Delete knowledge file
  • POST /api/assistant/admin/:adminId/create — Create/recreate assistant

13. Deployment & Infrastructure

Platform

Deployed on Replit with automatic builds, TLS, and health checks. The application runs as a single process serving both the Express API and the Vite-built React frontend.

Build Process

# Development npm run dev # Starts Express + Vite dev server # Production Build npm run build # Bundles React app + compiles server npm run start # Runs production server # Database npm run db:push # Sync Drizzle schema to PostgreSQL

File Storage

All uploaded files (images, PDFs, attachments) are stored in Replit Object Storage. Files are accessed via the /objects/* route which proxies to the cloud storage bucket. A migration endpoint exists to move legacy local files to cloud storage.

Session Storage

Sessions are persisted in PostgreSQL via connect-pg-simple, ensuring sessions survive server restarts.

Performance Optimizations

  • Weather API responses cached in weather_cache table with expiry
  • Frontend uses React Query with automatic caching and background refetching
  • Images use lazy loading (loading="lazy")
  • Weather auto-refreshes hourly (60-minute refetch interval)
