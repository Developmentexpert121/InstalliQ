Local Development Setup

Everything you need to run the app on your own machine.

Prerequisites

Runtime
Node.js 20.x
Download at nodejs.org
Package manager
npm 10+
Ships with Node 20 — no separate install needed
Database
PostgreSQL
Local install or point at the DigitalOcean DB

Step 1 Install dependencies

Open a terminal in the project root and run:

npm install

Step 2 Create your .env file

Create a file named .env in the project root. The dev server reads it automatically. Fill in the values from the sections below. 

# ─── DATABASE (pick one) ──────────────────────────────────────────────────
# Option A: DigitalOcean managed database (shares production data — use carefully)
DIGITALOCEAN_DATABASE_URL=postgresql://user:password@host:port/dbname?sslmode=require

# Option B: Local PostgreSQL (recommended for safe testing)
DATABASE_URL=postgresql://localhost:5432/installiq

# ─── REQUIRED ──────────────────────────────────────────────────────────────
SESSION_SECRET=any-long-random-string-at-least-32-characters
SIGNSUITEIQ_SSO_SECRET=must-match-production-value-for-companycam-tokens

# ─── AI FEATURES (image analysis, scheduling, PDF parsing) ────────────────
OPENAI_API_KEY=sk-...

# ─── FILE UPLOADS (photos, PDFs, exports) ─────────────────────────────────
DO_SPACES_KEY=your-digitalocean-spaces-access-key
DO_SPACES_SECRET=your-digitalocean-spaces-secret-key
DO_SPACES_ENDPOINT=https://nyc3.digitaloceanspaces.com
DO_SPACES_BUCKET=productionstorage
DO_SPACES_CDN_URL=https://productionstorage.nyc3.digitaloceanspaces.com

# ─── EMAIL (welcome emails, survey PDFs, schedule confirmations) ───────────
SMTP_HOST=smtp0001.neo.space
SMTP_PORT=587
SMTP_USER=your-smtp-username
SMTP_PASS=your-smtp-password

# ─── PAYMENTS (Razorpay subscription plans) ───────────────────────────────
RAZORPAY_KEY_ID=rzp_...
RAZORPAY_KEY_SECRET=your-razorpay-secret

# ─── WEATHER (calendar forecast strip) ────────────────────────────────────
OPENWEATHER_API_KEY=your-openweather-key

# ─── GOOGLE CALENDAR INTEGRATION ──────────────────────────────────────────
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret

# ─── SENDGRID (optional email sender verification) ────────────────────────
SENDGRID_API_KEY=SG....

# ─── APP BASE URL (used in email links) ───────────────────────────────────
BASE_URL=http://localhost:5000

Step 3 Set up the database schema

Option A — Local PostgreSQL

Create the database, then push the Drizzle schema:

createdb installiq
npm run db:push

Option B — DigitalOcean database

The schema is already in place on the live database. Skip db:push — running it against production is safe (Drizzle only adds missing columns/tables) but double-check before applying.

⚠️
Production data warning. If you point DIGITALOCEAN_DATABASE_URL at the live database, any users or projects you create locally will be real data. Use a local Postgres instance for day-to-day development and reserve the DigitalOcean connection for read-only debugging.

Step 4 Start the app

npm run dev

The frontend and backend both run on http://localhost:5000 — no separate commands needed. When the server starts it prints a summary of which environment variables are set and which are missing; check that output if anything isn't working.

Tips & Common Issues

💡
Check the startup log. When you run npm run dev the server prints an environment report listing every missing variable. Read that output first if something isn't working.
🔑
SIGNSUITEIQ_SSO_SECRET must match production. This key is used to AES-256-GCM encrypt CompanyCam API tokens already stored in the database. If it doesn't match, decryption will fail and CompanyCam integrations will appear broken even though the tokens exist.
🛢️
Local Postgres is the safest choice. Restore a database dump from production for realistic data, or start fresh and create a super-admin account through the seeder. Either way you won't risk touching live records.
  • Port conflict? The app defaults to port 5000. Set PORT=3000 (or any free port) in your .env to change it.
  • SSL errors with local Postgres? Use DATABASE_URL (not DIGITALOCEAN_DATABASE_URL) — the app only enables SSL for the DigitalOcean connection.
  • Schema out of date? Run npm run db:push after pulling new changes that include schema updates.
  • File uploads not working locally? Either supply the DigitalOcean Spaces credentials in .env or expect upload routes to return errors — the rest of the app will still function normally.
